## 1. Why non-goals are normative

Every definition says what a thing is. Only some definitions also say what it is not, and those are the ones that survive contact with a market. A non-goal here is not a deferral; it is a boundary that protects the authority of the term.

## 2. The five non-goals

### 2.1 AOP is not AI

Agentic execution may use AI, but AI is a technology. AOP is an operational specification. A procedure written to be executed by a model and a procedure written to be executed by a rules engine differ in their requirements for determinism, evidence and assurance, but they are the same class of artefact: a governed operating standard.

### 2.2 AOP is not automation

Automation executes predefined mechanisms. Agentic execution may interpret context and determine an appropriate course of action within its authority. The distinguishing feature is not the sophistication of the executor; it is whether the execution path is determined at authoring time or at execution time.

### 2.3 AOP is not autonomy

Agentic describes a mode of operation. Autonomous describes the degree of independent execution. An AOP can govern fully supervised, partially autonomous or highly autonomous execution. Conflating the two produces procedures that are sold as autonomous and are neither specified nor safe.

### 2.4 AOP is not an Agent Skill

A skill provides a reusable capability. An AOP governs the operational use and coordination of capabilities. A skill without an AOP has no authority to act; an AOP without skills has nothing to invoke.

### 2.5 AOP is not an Agent Harness

The AOP defines what must be achieved and the boundaries within which execution occurs. The harness provides the controlled environment that enables and enforces that execution. The harness is the top-level AOP for its domain; it is not a substitute for one.

## 3. The misconception ladder

Each entry is a misreading that is common, and the correction that replaces it.

| Misreading | Correction |
|---|---|
| An AOP is an SOP written for an agent. | An SOP is authored from intent and is linear. An AOP is compiled from observation and is a network of variants, decision points and exception edges. The difference is in the artefact class, not the vocabulary. |
| An AOP is a prompt. | A prompt states an instruction. An AOP states intent, context, constraints, authority, capabilities, coordination, control and assurance. Authority and evidence obligations have no prompt equivalent. |
| An AOP is a workflow definition. | A workflow defines a flow. An AOP defines the authority under which flow may adapt, and the evidence that the outcome was correct. The flow is one of its components. |
| An AOP replaces human accountability. | It relocates it. In agentic operations, humans hold exception ownership rather than corridor execution. Accountability does not disappear; it moves to the decisions that actually need judgement. |
| An AOP makes an agent safe. | It makes an agent governable. Safety is an outcome that depends on the harness, the environment and the assurance regime, not on the document alone. |
| An AOP can be written from an SOP. | It can be derived from one, but the derivation is the six-stage procedural engineering process. A straight transcription produces a degraded artefact that cannot support an agent. |
| An AOP is a policy. | A policy states a rule. An AOP states an objective, the rules in force, who may decide what, and what evidence demonstrates the outcome. It contains policies; it is not one. |
| An AOP applies to one agent. | It applies to a class of execution instances. A single AOP governs multiple agents, multiple harnesses and multiple scenarios. |

## 4. Adjacent concepts that are not the same

| Concept | Relation to AOP |
|---|---|
| Standard Operating Procedure | Source material and lineage. An AOP is compiled from observed work; an SOP is authored from intent. |
| Agent Skill | A capability invoked by an AOP. |
| Domain Agent Harness | The top-level AOP for a domain. It governs the agents inside it. |
| Business process model | A record of intended process. AOP adds authority, control and assurance obligations, and is compiled rather than drawn. |
| Policy engine | Evaluates rules against a decision. An AOP states the rules, the decision rights, and the evidence obligation; an engine evaluates what is given to it. |
| Runbook | A document that helps an operator act. An AOP specifies what the actor may decide, not only what to do. |
| Observability | Measures the system. An AOP states what evidence is required; observability supplies it. |
